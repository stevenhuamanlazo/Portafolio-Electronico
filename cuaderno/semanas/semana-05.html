    (Desarrollar una aplicación frontend con un framework JavaScript)

    React, SPA y diferencia entre librería y framework

    React es una librería de JavaScript para crear interfaces de usuario con componentes reutilizables. Una SPA (aplicación de página única) carga una sola página y actualiza el contenido sin recargar el navegador. Una librería la uso yo cuando la necesito, y un framework define la estructura y es quien llama a mi código (inversión de control). React es técnicamente una librería, pero con sus herramientas se usa como framework.

    Diferencia entre librería y framework
    AspectoLibreríaFramework
    Control del flujoLo tiene el desarrolladorLo tiene el framework
    EstructuraLibreDefinida por el framework
    EjemploReactNext.js y Angular
    Client Side Rendering y Server Side Rendering

    En el Client Side Rendering el servidor entrega un HTML casi vacío y un archivo JavaScript, y el navegador construye la interfaz. Después de la carga inicial la navegación es más rápida y el servidor trabaja menos, pero el primer acceso es más lento y el SEO se ve afectado. En el Server Side Rendering, como en Next.js, el HTML lo construye el servidor.

    Node.js, NPM y gestión de dependencias

    Node.js permite ejecutar JavaScript fuera del navegador; se recomienda la versión LTS y se comprueba con node -v. NPM viene con Node.js e instala, actualiza y elimina las dependencias de un proyecto. Estas se registran en package.json y sus archivos se descargan en node_modules. La gestión de dependencias es controlar de qué librerías depende el proyecto.

    Componentes, JSX, props y children

    El desarrollo basado en componentes divide la interfaz en piezas independientes y reutilizables. En React un componente es una función de JavaScript con nombre en mayúscula que retorna JSX, y se anidan formando un árbol que parte de App. JSX permite escribir estructuras tipo HTML dentro de JavaScript; el navegador no lo entiende, así que lo transpilan Babel o SWC. Debe devolver un único elemento raíz y los valores se insertan con llaves. Las props son los datos que el componente padre envía al hijo; el hijo no puede modificarlas, por eso el flujo de datos es de padre a hijo. Children es una prop especial con lo que va entre la etiqueta de apertura y cierre, útil para tarjetas o layouts.

    2. Ejercicios de laboratorio - Resultados

    Ejercicio

    Ejercicio 1: Práctica individual del curso práctico: crear 3 proyectos React desde la terminal, cada uno con una herramienta distinta (Create React App, Vite y Next.js), ejecutarlos en local y comparar la estructura de carpetas que genera cada una.

    Procedimiento
    1. Desarrollo de las clases en la hora de teoría y en la hora de práctica.
    2. Instalación de Node.js en su versión LTS y comprobación con node -v.
    3. Creación de los tres proyectos con sus comandos: npx create-react-app, npm create vite@latest y npx create-next-app@latest.
    4. Ejecución de cada proyecto en local para verificar que funciona, y compilación del proyecto de Next.js con el comando de build.
    5. Revisión de las carpetas y archivos de cada proyecto en Visual Studio Code.
    6. Actualización del cuaderno de la asignatura.
    Resultado

    Los tres proyectos se ejecutaron correctamente en local. Create React App tiene las carpetas node_modules, public y src, y su index.html está dentro de public. Vite pone el index.html en la raíz y agrega vite.config.js y eslint.config.js. Next.js organiza la aplicación en la carpeta app, genera la carpeta .next al compilar y, durante la instalación, permite elegir opciones como Tailwind CSS.

    Observaciones

    Los tres proyectos usan React 19: Create React App con react-scripts 5.0.1, Vite con su servidor de desarrollo y Next.js 16 con TypeScript y Tailwind CSS 4.

    En la estructura comparada se nota que Create React App y Vite usan src como carpeta de código, mientras que Next.js usa app, y que solo Vite lleva el index.html en la raíz.

    El proyecto de Next.js generó además los archivos AGENTS.md y CLAUDE.md.

    3. Reflexión: ¿Qué aprendí? y ¿Cómo aprendí?

    ¿Qué aprendí?

    Aprendí a diferenciar una librería de un framework a partir de la inversión de control, y entendí que React es técnicamente una librería pero con sus herramientas se emplea como un framework. Comprendí cómo funciona el Client Side Rendering, donde el navegador construye la interfaz a partir de un HTML con un único div root, y su diferencia con el Server Side Rendering de Next.js. Conocí el rol de Node.js y NPM en la gestión de dependencias con package.json y node_modules, y las herramientas de cada etapa: Babel para transpilar, Webpack para compilar y ESLint para la calidad del código. Entendí cómo los componentes dividen la interfaz en piezas reutilizables escritas en JSX, y cómo las props y children pasan datos y contenido del padre al hijo. También aprendí a crear 3 proyectos con Create React App, Vite y Next.js comparando sus estructuras, y las formas de aplicar estilos en React: inline, style sheets, style modules, styled components y frameworks CSS.

    ¿Cómo aprendí?

    En la hora de teoría se explicaron los fundamentos de React, las herramientas del entorno y los conceptos de componentes, JSX, props, children y estilos. En la hora de práctica instalé Node.js LTS y comprobé que funcionara desde la terminal. Luego creé los 3 proyectos con sus respectivos comandos, los ejecuté en local para verificar su funcionamiento y, finalmente, revisé las carpetas y archivos de cada uno en Visual Studio Code.
