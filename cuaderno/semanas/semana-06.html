    Cómo renderiza React: DOM virtual y reconciliación

    React no modifica la página directamente. Primero crea un DOM virtual en memoria; cada vez que un componente cambia genera uno nuevo y lo compara con el anterior (diffing). Con esa diferencia, la reconciliación actualiza en el DOM real solo las partes que cambiaron. El renderizado se hace sobre un elemento HTML con id root, con ReactDOM.createRoot(...).render(<App />).

    Componentes: clase y función

    Un componente es una unidad de interfaz reutilizable. Se crea en un archivo .jsx o .tsx, su nombre debe empezar con mayúscula y se invoca como una etiqueta (<Header />). Todo componente tiene tres partes: el JavaScript, el HTML (JSX) y el CSS. Existen componentes de clase (class X extends React.Component con render()) y de función, que se escriben con mucho menos código y son los que usé en las prácticas.

    JSX: expresiones, condicionales y listas

    JSX mezcla JavaScript con HTML y requiere que un transpilador como Babel lo convierta a JavaScript. Dentro de las llaves { } puedo insertar variables, atributos y expresiones como {2000 + 24}. Un componente debe devolver un solo elemento raíz (un div o un fragmento <></>) y todas las etiquetas deben cerrarse, incluso las que no tienen cierre en HTML (<input />).

    Props y children

    Las props son los datos que un componente padre envía al hijo como atributos; llegan como un objeto y el hijo no debe modificarlas. Children es lo que se escribe entre la etiqueta de apertura y cierre del componente (<Hijo>texto</Hijo>) y el hijo lo recibe con {children}. También se pueden anidar componentes dentro de otros (<App /> contiene a <Padre />, que contiene a <Hijo />). Para que un hijo envíe un dato al padre se pasa una función por props.

    TypeScript en componentes

    TypeScript es JavaScript con tipado estático opcional: detecta errores antes de ejecutar el código. En un componente se define una interface con los tipos de las props y se usa React.FC<Props>; por ejemplo, number: number y setNumber: Dispatch<SetStateAction<number>>. Un archivo con JSX en TypeScript usa la extensión .tsx.

    Enrutamiento en el cliente con React Router

    En una SPA el routing del lado del cliente cambia la vista sin recargar la página. BrowserRouter envuelve la aplicación, Routes agrupa las rutas y cada Route asocia un path con un componente; la ruta * sirve para la página 404. NavLink reemplaza al <a> y, mediante la función isActive (que sustituye al antiguo activeClassName), permite resaltar el enlace de la página actual.

    Consumo de API con axios y async/await

    Con axios se crea una instancia con baseURL y timeout, y las peticiones se hacen con async/await dentro de try/catch/finally en lugar de encadenar .then(). En useEffect se manejan tres estados: loading, data y error. El AbortController permite cancelar la petición cuando el componente se desmonta (función de limpieza del efecto), así se evitan renders innecesarios. En desarrollo, StrictMode monta el componente dos veces y por eso se ven dos peticiones, la primera cancelada.

    Formularios controlados y eventos

    En un formulario controlado el valor de cada campo vive en un estado (useState) y se actualiza con onChange, de modo que React siempre sabe qué hay escrito y puede validarlo en tiempo real. En onSubmit se llama a e.preventDefault() para que la página no se recargue. El mismo principio sirve para el buscador de la lista: el texto escrito filtra el arreglo sin volver a pedir datos a la API.

    3. Reflexión: ¿Qué aprendí? y ¿Cómo aprendí?

    ¿Qué aprendí?

    Aprendí cómo React actualiza la página con el DOM virtual, el diffing y la reconciliación, y a construir interfaces con componentes de función escritos en JSX, pasando datos con props y children. Entendí cómo se muestra contenido de forma condicional (&&, ternario) y en listas con .map() y una key única, y las formas de dar estilos: hojas CSS, módulos, estilos en línea y Tailwind. En la práctica aprendí a crear una SPA con rutas del lado del cliente usando BrowserRouter y NavLink, a consumir una API con axios y async/await manejando los estados de carga y error, y a cancelar peticiones con AbortController. También comprendí cómo funciona un formulario controlado con validación en tiempo real y por qué el HTML de una SPA llega casi vacío (CSR).

    ¿Cómo aprendí?

    Combiné la actividad 07A del curso teórico con la práctica guiada del curso práctico: primero leí la teoría de cada concepto y luego lo apliqué paso a paso en el proyecto Minimarket Fresco, probándolo en el navegador y revisando la pestaña Network de DevTools. Los errores me enseñaron más: por ejemplo, ver dos peticiones en desarrollo me llevó a entender StrictMode y el AbortController, y que los productos nuevos no aparecieran en el catálogo me llevó a guardarlos en localStorage. Cuando usé IA para resolver un problema de estilos o de props, lo dejé documentado en un comentario con la solución que apliqué a mano.
