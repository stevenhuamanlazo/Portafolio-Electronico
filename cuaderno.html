    REGISTRO SEMANAL

    Semana 1

    1. Descripción de temas aprendidos con mis propias palabras

    (Definiciones y procedimientos)

    Esta semana aprendí que no todo lo que está en internet es lo mismo. Una página web es un documento al que se entra con una URL; un sitio web es un conjunto de páginas conectadas bajo un mismo dominio; una aplicación web corre en un servidor y reacciona a lo que hace el usuario (por ejemplo Gmail); y un sistema web junta varias aplicaciones, servicios y bases de datos para resolver un problema grande, como el sistema de matrícula de la UNCP.

    También entendí el recorrido de una petición: el DNS traduce el nombre del dominio a una dirección IP, TCP/IP divide la información en paquetes y la envía por la red, y HTTP/HTTPS organiza la conversación: el navegador envía un Request (GET o POST) y el servidor responde con un Response (200 OK, 404 Not Found).

    1. Navegador
    2. DNS
    3. TCP/IP
    4. HTTP/HTTPS Request
    5. Servidor
    6. Response

    La web se basa en estándares abiertos: HTML da la estructura, CSS el aspecto y JavaScript la interactividad, y organizaciones como el W3C los mantienen para que ninguna empresa controle la web. El desarrollo se divide en Frontend (lo que se ve y se ejecuta en el navegador), Backend (la lógica, las APIs y la base de datos en el servidor) y Fullstack (dominar ambas capas).

    Aprendí también que Git es un sistema de control de versiones y GitHub el lugar donde se aloja el repositorio, lo que permite guardar el historial de cambios y publicar el código.

    Finalmente, con la infografía aprendí a elegir un hosting según las necesidades del proyecto. Los planes gratuitos (Vercel, Render, Supabase) sirven para practicar, pero tienen límites: poca memoria, servidores que se duermen por inactividad y restricciones de uso comercial. Los planes de pago (Vercel Pro, Heroku, PlanetScale) ofrecen dominio personalizado, HTTPS/SSL, CDN, despliegue automático, escalabilidad y soporte.

    2. Ejercicios de laboratorio - Resultados

    Ejercicio

    Ejercicio 1: Laboratorio 01A, configuración de Visual Studio Code y creación de mi tarjeta de presentación web publicada en GitHub.

    Ejercicio 2: Infografía grupal con la recomendación de hosting para la empresa "Textiles Andinos" S.A.C.

    Procedimiento

    Ejercicio 1

    1. Instalé Visual Studio Code y abrí la carpeta Laboratorio01_Web.
    2. Identifiqué las áreas de la interfaz: barra de actividad, barra lateral, editor, panel y barra de estado.
    3. Instalé las extensiones Live Server, Prettier, Material Icon Theme y ES7+ React snippets.
    4. Practiqué atajos de teclado: Ctrl+P, Ctrl+Shift+P, Ctrl+D, Alt+↑/↓, Ctrl+/ y ! + Tab (Emmet).
    5. Creé index.html con la estructura base y agregué mi foto, nombre, carrera, un párrafo sobre el rol que me interesa y mis enlaces.
    6. Lo abrí con Live Server para ver los cambios en tiempo real.
    7. Ejecuté git init, git add ., git commit -m "Práctica 01: Fundamentos y VSC" y git push al repositorio público portafolio-web-uncp.

    Ejercicio 2

    1. Analicé el caso: la empresa necesita un sitio web administrable (CMS) con galerías de alta resolución, blogs y cotizaciones B2B, con contrato de 3 años.
    2. Investigamos servicios gratuitos (Vercel, Render, Supabase) y de pago (Vercel Pro, Heroku, PlanetScale).
    3. Comparamos según disponibilidad, rendimiento, seguridad, escalabilidad y facilidad de administración.
    4. Calculamos el costo total y diseñamos la infografía en Canva.
    Resultado

    Ejercicio 1: Una tarjeta de presentación que se visualiza en el navegador con Live Server, y un repositorio público en GitHub con los archivos index.html y foto.jpg.

    Ejercicio 2: Una infografía que recomienda un hosting de pago, porque los planes gratuitos no permiten uso comercial y se duermen por inactividad. Costo estimado: US$600 al año, US$1800 por los 3 años.

    Observaciones

    Al enlazar el repositorio apareció el error remote origin already exists, porque el remoto ya estaba configurado. Lo resolví continuando con git branch -M main y git push -u origin main, y el envío funcionó. Noté que Live Server actualiza el navegador automáticamente sin recargar. En la infografía trabajamos en equipo de 6 integrantes y vimos que el hosting gratuito no sirve para una empresa que necesita estar siempre disponible.

    3. Reflexión: ¿Qué aprendí? y ¿Cómo aprendí?

    ¿Qué aprendí?

    Aprendí a diferenciar página, sitio, aplicación y sistema web, y a entender cómo viaja una petición desde que escribo una dirección hasta que el servidor responde. También aprendí a configurar mi entorno de trabajo en VSC, a publicar mi código con Git y GitHub, y a elegir un hosting pensando en disponibilidad, rendimiento, seguridad y crecimiento del proyecto, no solo en el precio.

    ¿Cómo aprendí?

    Primero con la clase teórica, que me dio los conceptos, y luego aplicándolos: configuré el entorno, practiqué los atajos sin usar el ratón y construí mi tarjeta paso a paso. En la infografía aprendí investigando en equipo las características de cada servicio y justificando la recomendación con números.

    Dificultad y solución

    Me apareció el error remote origin already exists al conectar con GitHub. Entendí que el repositorio remoto ya estaba enlazado, así que bastó con hacer el push a la rama main. Eso me ayudó a comprender mejor cómo se relacionan el repositorio local y el remoto.
